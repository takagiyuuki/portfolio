# ADR-0024: Work のエントリはリンクを行き先ごとに分け、tech を VT323 のタグにする

Date: 2026-10-16
Status: Accepted

## Context

Work ページ（#19）の 1 エントリは、行き先を最大 3 つ持つ。ライブサイト（`live`）、
ソースコード（`repo`）、解説記事（`article`）である。読み手によって見たいものが違う。
採用担当者は動くもの、エンジニアはコード、設計の背景を知りたい人は記事を見る。

個人サイトのプロジェクト一覧では、カード全体を 1 つのリンクにし、hover で背景や文字色を
変える作りが多い。参考にした 2 つのサイトは、どちらも **1 カードに行き先が 1 つ**だった。

このサイトのデザインは ADR-0019 で chrome（nav・footer）に VT323 を使い、本文は Inter に
限っている。

## Decision

### カード全体をリンクにしない

各リンクだけを押せるようにし、エントリの領域には hover の変化を付けない。

- `<a>` の中に `<a>` は置けないので、カード全体を `<a>` で囲む方法は使えない
- 空の要素でリンクの範囲をカード全体に広げる方法（stretched link）は使えるが、
  カードを押したときにどの行き先へ飛ぶかが、見た目から分からなくなる
- 押せない領域を hover で変化させると、押せるように見えてしまう

### 行き先ごとのリンクの置き方

| 行き先 | 置き方 |
| --- | --- |
| `live` | タイトル（`h2`）をリンクにする。最も見てほしい行き先を最も目立つ位置に置く |
| `repo` | GitHub のマークと "Source code" のテキストを並べたリンク |
| `article` | "Read the article" のテキストリンク。記事があるエントリだけ出す |

- 外部リンクの書き方は ADR-0023 に従う（`ExternalLink`）
- このサイト自身のエントリには `live` を書かない。閲覧中のサイトを新しいタブで開いても
  読み手には何も得られない
- GitHub のマークだけのリンクにはしない。文字を添えると、リンクの色・下線・告知が
  他の本文リンクと揃い、何のリンクかも文字で伝わる

### エントリを面や枠で囲まず、区切り線で区切る

エントリに背景も枠線も付けない。エントリとエントリの間にだけ 1 本の罫線
（`--color-border`、Flexoki の `ui`）を引く。

- Flexoki は背景の段階（`bg` / `bg-2`）と罫線の段階（`ui` / `ui-2` / `ui-3`）を分けて定義
  しており、罫線の段階は入力欄や表の線のような状態の違いを表す。罫線は表の線のように
  文章になじむ強さで設計されており、面の輪郭に使うには薄く、`bg-2` の面は本文の中で
  浮いて見えた
- エントリ間の線は design.md の「内容の区切りに必要な箇所だけに罫線を引く」に当たり、
  装飾の規則は変えない
- 面が無いので、説明文には `--color-text-muted` が使える（対 bg で AA を満たす。
  `bg-2` の上ではライトで 4.47 になり下回る）
- エントリは 1 列に並べる。面も枠も無いエントリを 2 列に並べると、どこまでが 1 件か
  読み取りにくい

### tech を VT323 のタグにする（ADR-0019 の範囲を広げる）

tech の各項目を、VT323・大文字・紫の背景のタグとして表示する。

- VT323 を使う範囲を **chrome と tech タグ**に広げる。ADR-0019 が chrome に限定した
  理由（散文の可読性、日本語のグリフが無いこと、名前の見え方）は、短い固有名詞が並ぶ
  タグには当てはまらない
- ADR-0019 の VT323 の規則をそのまま適用する。**サイズと余白は整数 px**（`--text-tag`
  18px）、**大文字**（DOM の表記は `TypeScript` のまま残る）、**latin のみ**
- 色は Flexoki の purple（`pu`）を使う。Flexoki が UI の役割を割り当てていない
  アクセントのうち、blue（`bl`）は Web でリンクを表す慣習の色で、cyan のリンクと
  混同されやすい。purple は magenta よりコントラストに余裕がある
- 文字はライト purple-600 / ダーク purple-400、背景はライト purple-50 / ダーク purple-950
  （比率 6.56 / 5.00）。枠線は付けない。色相の違う背景だけでタグとして識別できる
- 紫の背景の上では muted の文字は AA を下回る（4.01 / 4.04）ので、タグの文字には
  専用の色を使う

## Rationale

### 却下した案: カード全体を 1 つの行き先へのリンクにする

stretched link で、常に `repo` へ、または `live` があれば `live`、無ければ `repo` へ
飛ばす案。前者は採用担当者がサイト名を押すと GitHub が開き、後者はカードによって
行き先の種類が変わり見た目から分からない。行き先が 1 つの一覧のための手法を、
行き先が複数ある一覧に持ち込むことになる。

## Consequences

- `ADR-0019` の「chrome のテキストは latin のみに保つ」は tech タグにも及ぶ。tech に
  日本語の項目を書かない
- tech の表記はデータ側で整える（`TypeScript`、`GitHub Actions`）。大文字化は表示だけで、
  データの表記は読み上げとコピーに残る
- タイトルの色はエントリによって揃わない（`live` があればリンク色、無ければ本文色）。
  色がリンクかどうかを正しく伝えている状態として受け入れる
- `.claude/rules/design.md` に、tech タグの書体・色・サイズ、`--color-border` の用途、
  `--text-small` を追記する
